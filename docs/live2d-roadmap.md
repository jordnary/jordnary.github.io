# 看板娘进阶建议

以下是后续设计建议，不表示这些功能已在本次实现。建议先让看板娘熟悉网站内容，再逐步增加角色反馈和个性化设置。

## 1. 优先接入页面联动

进入「项目」时提供项目导览，进入「学习」时提示笔记分类，在搜索无结果时给出替代关键词。建议由页面显式传入当前栏目、目标条目和事件，避免让看板娘扫描整页内容、依赖容易变化的样式类名。

可定义简短的事件集合，如 `page-enter`、`project-open`、`search-empty`、`copy-success`；每条响应包含台词、可选动作、优先级、冷却时间和最多展示次数。用户主动点击的台词优先于自动提示，同类事件在同一访问中只提示一次，自动提示之间建议至少间隔一分钟。关闭搜索、滚动和鼠标每次进入都不应反复问候。

成熟的 [Live2D Widget](https://github.com/stevenjoezhang/live2d-widget) 已通过配置文件组织工具和基于选择器的提示触发规则。适合借鉴其配置驱动方式；本站使用 React，可以把触发来源进一步变成明确的组件事件。这里的事件结构和频率是针对本站的设计建议。

## 2. 让工具列保持简洁

后续可依次接入「站内搜索」「随机笔记」「外部主页」和「收起」。优先保留三到四个高频入口，更多功能放进一个有文字说明的二级面板，避免整列继续拉长。外链图标和提示应表达将离开本站；跳转交给用户点击，人物提示本身不自动跳转。

当前 `CompanionAction` 已支持原生按钮回调和链接，可以在布局层按页面组合配置。后续可增加显隐条件、禁用原因和分组，但不应把具体页面业务写入模型渲染器。按钮尺寸、动效和提示仍统一维护。

## 3. 从随机短句升级为角色反馈

现已建立「待机 → 注意到用户 → 回应 → 恢复待机」的状态流程，区分摸头、招呼和成功操作反馈，并在回应期间暂停鼠标注视叠加。具体素材、触发区域和恢复策略见 [看板娘说明](./live2d.md)。

[pixi-live2d-display 的完整指南](https://github.com/guansss/pixi-live2d-display/wiki/Complete-Guide) 提供动作组、动作优先级、表情和手动交互机制。当前接入 `Idle`、`HeadPat`、`Greeting`、`Complete` 四组；`Expressions` 仍为空。若进一步增加独立情绪，需要另行制作并验证表情配置。

头部和身体现已使用语义部位与实际可见像素判定。开发检查页面支持部件隔离预览和不同缩放下的命中核验；后续更换模型时需要重新核对部件层级及命中网格。

## 4. 增加位置与阅读偏好

提供「标准 / 较大」尺寸、「左侧 / 右侧」位置以及「安静模式」。尺寸与位置按桌面浏览器保存，切换窗口时限制在视口安全区内。安静模式停用主动气泡，仍保留用户点击回应；需要完全沉浸阅读时仍可直接收起。

[PPet](https://github.com/zenghongtu/PPet) 的功能清单包含调整渲染大小、拖动位置和忽略点击，说明这几项是桌面角色控件已有的交互方向。对本站的建议是先用预设位置与尺寸：实现清晰、恢复容易。若以后加入自由拖动，应使用长按或独立拖动手柄，拖动完成不触发聊天，并支持一键恢复位置。

## 5. 完善资源加载和运行状态

继续保留桌面按需加载、后台暂停与收起释放。下一步可在测得首屏完成后再启动模型，缓存带版本号的静态资源，并记录加载时间、帧耗时与 WebGL 恢复结果，用数据判断是否需要调整帧率。

为 WebGL 上下文丢失、网络离线、动作加载失败分别设计恢复路径。可增加轻量静态立绘作为失败兜底；恢复动画后无缝切回。不要因为一个动作失败就让整个角色消失。人物进入长时间待机时可以降低帧率，有交互再恢复；具体阈值应根据实际设备测量。

## 6. 最后考虑站内问答与语音

当前「聊天」是预写台词轮播。若升级为真实问答，优先让它回答网站上的项目、学习笔记和联系方式，并给出可点击的站内来源。界面应区分欢迎语、正在查找、回答完成和暂时无法回答；缺少资料时直接说明，不替站主编造经历。

服务端保管接口凭据，设置请求限流和超时；访客明确输入后才发送消息。默认不长期保存聊天记录，提供清空当前会话入口。访问页面或鼠标悬停不自动发送整页内容。

语音适合放在文字问答稳定之后，以用户主动开启为前提。先做可停止的短句播报，再处理口型。当前模型列出了 `ParamMouthOpenY`，仍需要独立验证其与现有动作的混合效果；参数存在不代表口型同步已可直接使用。官方提供 [Web 音量驱动口型教程](https://docs.live2d.com/en/cubism-sdk-tutorials/native-lipsync-from-wav-web/)，可作为技术调研入口。

## 建议的实施顺序

| 阶段 | 内容 | 验收重点 |
| --- | --- | --- |
| 第一阶段 | 页面事件、三到四个图标入口、提示冷却 | 导览有用，提示不重复，页面操作不被抢占 |
| 第二阶段 | 表情与动作状态、尺寸位置、安静模式 | 动作不冲突，偏好可恢复，长文阅读舒适 |
| 第三阶段 | 加载与资源恢复优化、站内问答 | 有真实来源，失败可恢复，资源开销可测量 |
| 第四阶段 | 可选语音与口型、更多角色内容 | 用户主动启用，停止响应及时，角色反馈一致 |
