本文是后续各轮工作的交接入口。目标是保留 React、Vite、现有页面设计和业务功能，重新确定资源何时请求、谁拥有请求、失败如何恢复，以及页面不可见时如何停止工作。优先级为：可操作与可恢复 > 视觉及交互连续性 > 内容及时出现 > 网络、CPU、内存开销。不得以减少功能、改变转场、降低原图能力或取消无障碍支持换取指标下降。

## 2. 测量方法与可复现基线

### 2.1 环境与口径

实测依赖来自现有 lockfile 和已安装版本：Node.js `24.15.0`、npm `12.2.0`、React/React DOM `19.2.7`、Vite `8.0.16`、Playwright `1.63.0`，浏览器为 headless Microsoft Edge `156.0.4314.58`。没有升级依赖。

使用新建的 Vite **生产预览**，不是开发服务器。响应式素材先重建，项目转场模板单独检查。构建复用现有有效 GitHub/RSS 快照，使用 `--ignore-scripts` 跳过会联网同步内容的生命周期脚本，避免基线同时改变内容。因此本轮不把该结果写成完整联网发布流程已验证。

`tests/ux-baseline.browser.mjs` 每种配置、每条路由重复 3 次；每次使用新的浏览器上下文测冷启动，随后在同一页普通重载测 HTTP 缓存复用。共 8 路由 × 2 配置 × 3 次 × 2 缓存状态 = 96 个样本。两种配置不并行，浏览器性能测量期间不运行其他浏览器测试或构建。

| 配置 | 视口 / DPR | CPU | 网络 |
| --- | --- | --- | --- |
| `desktop` | 1440 × 900 / 1 | 不节流 | 本地预览，不节流 |
| `mobile-constrained` | 390 × 844 / 3，触控 | 4 倍降速 | 下行 1.6 Mbit/s，上行 0.75 Mbit/s，150 ms latency |

默认保留动效；看板娘按产品默认折叠。这里的移动端是浏览器模拟，不是真机结论。普通重载可能触发项目页原有 reload 转场，也不等同于 SPA 返回。`warm-reload` 只复用前一次采样期间完成的缓存，不提前强制加载所有图片；前次尚未完成的图片仍可能需要下载。

| 字段 | 定义及限制 |
| --- | --- |
| `readyMs` | `main` 出现页面子元素后的下一次 rAF；表示路由挂载，不能冒充 TTI、页面已可操作或转场已结束。 |
| `fcpMs` / `lcpMs` | 浏览器 PerformanceObserver 的 FCP / 采样截止前最后一个 LCP 候选；不交互、不等待所有图片和字体。 |
| `cls` | 排除近期输入，按 1 秒间隔、5 秒窗口累计的最大布局偏移会话值。 |
| `longTaskMs` / `blockingMs` | 导航开始至采样时的长任务总时长 / 每个长任务超出 50 ms 的部分之和；后者不是 Lighthouse TBT，也不是 INP。 |
| `sampledAtMs` | 路由挂载被测试驱动检测到后再观察约 2 秒的实际截止时间；记录此值用于解释尚未完成的资源。 |
| `network` | CDP 按类型记录发起、完成、失败、待完成、直接缓存命中、304 校验及完成请求的 `encodedDataLength`。含文档；未完成请求已经收到的部分字节未计入，完成量是传输下界，必须连同待完成数一起看。 |
| `resourceBodyBytes` | Resource Timing 中已完成资源的编码正文大小；可能来自缓存，不能当作网络实际传输量。 |
| 构建 `gzipBytes` | 对磁盘产物单独 gzip 的理论压缩大小；本地预览传输口径与线上 CDN 可能不同。 |

没有收集真实用户 INP/p75、Safari/Firefox、真实低端设备功耗、GPU 内存、长期堆泄漏或正式部署的缓存响应头。这些保留为后续验证项，不填写推测数字。当前基线中的 LCP/CLS 只是固定窗口实验室观察值，不用于宣称 Core Web Vitals 达标。

## 4. 替代设计

### 4.1 优先级与所有权

采用浏览器原生加载、Vite 的 CSS/模块依赖管理和 React 的展示边界；只在业务需要处增加小型策略。不要引入覆盖所有 DOM、fetch、字体、GPU 和动画的通用资源引擎。

| 类别 | 示例 | 启动与终止规则 |
| --- | --- | --- |
| 当前必需 | 首屏路由、当前主要图片、点击目标、已打开搜索、展开模型 | 立即启动，不能排在后台 idle 队列；页面正常加载保持安静，失败显示短暂通知；功能内原有反馈保留；更换目标用 generation 防止旧结果覆盖。 |
| 明确意图 | 同源路由稳定 hover/focus、当前图邻居、阅读器入口聚焦 | 优先热身小资源；真正点击提升为必需并复用同一个任务。 |
| 临近可见 | 屏幕附近的展示图片、即将进入的阅读器装饰 | 优先 native lazy/IO；离开生命周期取消尚未开始的任务；不把所有字体、原图和路由一并预热。 |
| 后台可选 | 无点击的预测、非必要维护 | 当前内容就绪且可见后才允许；页面隐藏、节流偏好或交互繁忙时不启动。无空闲 API 时使用可取消定时兜底，不能阻塞产品功能。[R4] |

只有意图预热需要小队列：初始上限为 **1 个运行中的推测任务、2 个待启动目标**，重复 key 合并，最新意图替换过期未启动项。当前必需任务绕过该限制；已发出的 import 不可假装中止或卸载。不得把缓存预算当作可以清除浏览器模块缓存的承诺。`saveData`/连接信息可用时收紧推测，不可用时采用保守默认；不依赖设备标签屏蔽实际功能。

组件卸载拥有自己的 observer、listener、rAF、timer 和可取消请求；共享请求必须有清晰消费者所有权，不能因一个消费者关闭就 abort 其他仍在使用的请求。尽量依靠少量具体接口，避免创建多个功能重叠的缓存。

### 4.2 启动、路由与失败恢复

1. 正常启动不创建加载提示或占位提示面板；React 可挂载后保留相应页面壳，真实内容就绪前不显示页脚。Portal 和项目入口不能短暂闪现普通页导航栏。不得移除 Vite 的 CSS 就绪保护来换取更早但无样式的内容。
2. 页内跳转继续保留旧页，正常等待不显示提示，也不为提示追加 rAF、定时器或最短展示时间。目标就绪后提交新内容；项目转场沿用现有节奏、输入保护、隐藏/减少动效分支和 reload boot。
3. 只有失败时显示右下角“页面加载失败”小红框，底部横条从满到空，默认 5 秒后沿原路滑出。点击、触摸或键盘激活先按压回弹再滑出；减少动效时立即关闭，倒计时条按秒缩短。不堆叠。重新点击目标链接可重试；拒绝的模块/CSS 使用完整文档导航恢复，超时继续复用原请求；入口失败用浏览器刷新恢复。通知内不增加重试、返回、取消等按钮。
4. `vite:preloadError` 与 Error Boundary 使用同一通知；不自动无限 reload，不吞错后清空当前页。8 秒加载超时与 2500 ms 项目遮罩预算独立保留。超时后释放输入与遮罩，晚到结果必须经过新的用户导航才能采用；通知关闭不清除失败模块记录。失败的 Back/Forward 在通知关闭后恢复保留页面的历史项。
5. hover/focus 预取只匹配现有同源路由，保留外链、新窗口、下载、修饰键和 hash 语义。先用 100 ms 稳定意图延时做实验；是否启用及最终阈值由点击延迟和无效下载量共同决定。

### 4.3 功能边界与资源规格

- 搜索保留轻量快捷键与打开控制，完整搜索 UI/索引作为功能块。点击后立即给反馈并保留输入；可在搜索按钮 hover/focus 时准备。不要让“首次按 Ctrl+K 无反应”成为拆包副作用。
- 图集保留现有 trigger、读图位置、滚动锁与 focus return；加载完整实现时仍允许取消。稳态最多当前和相邻原图，所有缩略图导航仍可用。跨图路径用合适分辨率的展示图/预览图维持连续穿行，当前与目标原图优先；沿途原图不再是整个路径的前置屏障。目标错误保留当前内容和错误反馈，快速改选只兑现最新目标。
- 先测实际 LCP 与绘制尺寸再新增图片 hints。Learning 两个层次的首屏图当前有防重复测试，不能因为“通常只预载一张”就直接删掉其中一个。扩展项目预览/正文展示尺寸，缩放保留原图。
- HomeNow 预热先缩减内容：边框、少量必要字形、实际需要的展示字体。评估将基础字体按常用及动态字形分片，但必须保留完整覆盖、许可证、原字体外观和 fallback。600 px 距离需在快速滚动后点击的实验中校准，不能直接改成点击后才加载全部 1.58 MiB 字体。
- 先从引用边界拆共享 CSS 和功能依赖；每次比较所有入口的首次与再次访问开销。不能只让 `main` 变小却导致常用跳转产生更多瀑布、重复样式或更晚显示。

### 4.4 缓存与更新

| 资源 | 推荐归属与失效 |
| --- | --- |
| 构建哈希 JS/CSS、响应式副本、打包头像 | 浏览器 HTTP 缓存及模块缓存；由内容地址失效。检查部署实际响应头，不在前端模拟 CDN 控制。 |
| 原图、字体、模型静态文件 | 优先使用现有 HTTP 缓存；需要长缓存时同步设计版本地址。不要再把这些二进制写入 localStorage 或新增 Service Worker。 |
| GitHub/RSS JSON | 同一轻量快照接口：校验 → 立即呈现可用旧值 → 有需要时 revalidate → 原子更新；进行中共享，失败保留数据。 |
| 解码图片、WebGL 纹理、rAF | 页面或功能生命周期持有；关闭释放应用持有对象和 GPU 资源。卸载 DOM 不等于浏览器会立即释放全部图片/网络缓存。 |

快照初始实验策略：会话内 freshness 5 分钟，按源更新时间最多接受 7 天的持久旧值；这些是可调产品策略，不是当前事实。超过 freshness 的有效数据带“上次更新/暂时无法更新”状态先显示，再校验；超过最大旧值上限时显示已有错误态和手动刷新。RSS 和 GitHub 保持一致语义，显式刷新绕过 freshness，但共享进行中请求。保存 schema/version/源更新时间，存储禁用或容量失败不得影响网络结果。没有用户操作或可见消费需求时不增加轮询。

### 4.5 调度与 Live2D

- 每个动画明确四个输入：所属页面/功能是否 active、页面是否可见、元素是否在相关视口、是否 reduced motion。仅对需要这些条件的动画复用小 hook，避免把多个独立动画改成 React 每帧 setState。
- Hub 在 hidden 时取消循环，恢复时重新排一帧；减少动态效果时保留静态网格和必要输入反馈。不得取消其原有视觉风格、桌面轨迹或移动端交互。
- 保留 Intro 的 WAAPI、已有 IO 暂停、指针轨迹静止收敛、30 FPS 私有 Live2D ticker 等有效机制；不要为统一代码而改回永久 rAF。
- Live2D 显式展开直接加载；记忆展开态等待页面可见及关键内容阶段后启动。把 rAF、idle 与 1 秒兜底收敛成一个可取消启动入口，用户点击可立即提升优先级。
- 重新画出 core script、运行时模块、模型文件与首帧的依赖；只有实际不依赖前一步的请求才并行。core loader 明确共享消费者/失败复位规则；模型资产继续共享 AbortSignal，释放 blob/纹理，保留有限重试、motion 冷却和 context recovery。没有测量证据前不改 GPU 分辨率、动作或加载超时。

**替代实现与清理：**

- `src/lib/pageStartup.ts` 与 `src/page-startup.css` 由 Vite 注入所有 HTML 入口，包括生成的项目详情页。入口 JS/CSS 尚未到达时已有可访问反馈；资源失败或等待 8 秒后显示重试与返回入口。React 挂载后接管反馈；入口超时后的晚到脚本不能自行抹掉错误状态。编码声明保持在 HTML 前 1024 字节。Portal、Projects 使用各自背景，不闪现普通导航栏。

- 首次 pending 只显示页面壳与反馈，页脚在真实内容就绪后出现，避免慢网时页脚先进入视口、随后被正文推走。项目 reload 在启动纸张已不透明时即可挂载就绪内容，不额外等待 covering 阶段结束；原有显示节奏和输入保护保留。

- 模块/CSS 失败和部署失效 chunk 通过用户点击“重试”或“重新打开页面”进行完整文档导航，获取新入口，不自动 reload。相同地址含 hash 时使用真正的 `location.reload()`，保留 query/hash。渲染失败可就地重新挂载；持续失败仍可重新打开或返回首页。

### 6.10 P3 首次构造与字体优化

**定位与实现：**

- 阅读器利用原有封面展开时正文尚不可见的阶段构造正文与动态内容。先读取源卡片背景，再集中设置样式，复用一次窗口尺寸；移除对尚未打开按钮的 React `autoFocus`，由原生 `showModal()` 聚焦第一个关闭按钮。标题构造前保留可访问名称，取消后不再挂载正文。

### 6.11 P3 搜索功能边界与成本验收

**成本定位与实现：**

- 原来的 `SiteLayout → SiteSearch → searchIndex` 是静态依赖链；搜索索引继续引用笔记、技能、时间线、个人介绍和项目数据。没有公共导航的 Portal 也支付这条共享依赖链的成本。现在 `SiteSearch` 仅保留快捷键、打开控制、输入框、关闭控件、等待/失败表面与焦点管理；结果列表、查询索引和结果样式在首次必需打开或合格意图时加载。
- `scripts/search-feature.ts` 从原数据生成搜索投影；39 条条目只携带搜索实际使用的字段，不再因为搜索而打包笔记示例代码及正文。项目元数据本来就属于路由依赖，由 `projectSearchEntries` 复用，不在新索引内再复制一份。生成在 Vite 构建/开发流程内完成，没有另存一份需要人工同步的索引文件。
- 搜索运行时代码只引用已加载的路由/JSX 共享模块。`tests/search-build-report.mjs` 遍历静态依赖，断言新增边界仅为搜索自身，搜索不能重新带入完整笔记或额外页面实现。实际搜索仍使用原来的大小写处理、空白分词、标题/关键词/描述权重、中文排序、默认 6 条和最多 8 条规则。
- 搜索按钮的 hover/focus/持续触摸直接加入 `page-prefetch.ts` 原有机制：100 ms 稳定意图、1 个运行目标、最多 2 个等待目标，沿用可见性、当前内容/图片/字体就绪、滚动和网络条件。搜索与路由共用队列，没有另加一套 idle 调度。显式点击与 `Ctrl/Cmd+K` 在事件中立即发起所需 JS/CSS，与轻量表面构造并行，不等待意图队列。
- `search-loader.ts` 是搜索任务的单一所有者，必需打开和预取复用同一 Promise。Vite 发出独立功能入口 URL；结果 CSS 由该所有者单独等待，两者都成功才呈现结果。失败的样式元素被移除，失败的 JS 根 URL 在用户重试时使用新尝试参数；成功或仍在进行的另一半继续复用，避免沿用失败的 CSS 标记而出现无样式结果。已有共享依赖不重新下载。
- 输入 DOM 从等待到成功保持同一个节点；输入、清空、重复快捷键、Tab、Esc、关闭按钮和背景点击在等待/失败时均可操作；已打开时的快捷键不在错误表面背后发起新的重试。关闭沿用原来的清空查询行为；加载完成不重开已关闭的表面。关闭归还原触发位置，移动菜单转交搜索后归还可见入口；结果导航仍由既有路由处理焦点、历史及锚点。
- 复用现有 8 秒消费者等待期限。超时后晚到资源不擅自覆盖错误态；重试可以直接使用已经到达的资源。关闭只取消消费者，不声称终止已发出的 import。过期部署还可显式重新载入文档：查询暂存于同页、60 秒内的一次恢复记录，重新打开后清除；存储不可用时保留当前输入并提示复制，不直接丢弃文字。
